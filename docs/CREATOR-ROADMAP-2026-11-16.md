# Creator Product Roadmap · 2026-11-16

状态：开发计划，非已实现功能。核心方向已由产品负责人确认；发布合作、费用、正式部署及具体定价尚未批准。本文件不触发派工、购买、模型调用或外部发布。

## 1. 产品范围

目标是独立品牌的自媒体创作工作台：发现资料 → 记录自己的观点 → 生成与编辑文章/口播稿/封面 → 下载内容包 → 排期及发布交接。保留通用 MCP，让外部 AI 与网页操作同一份内容。

- 免费社区版：原工作台、内容管理、手工编辑、导出、MCP、自带模型/API，以及可选 Magpie。开源软件免费不代表第三方 API 免费。
- 云端商业版：注册、工作区、私有存储、可靠任务执行与积分消费。收费价值是生成、制作和托管服务，不是对免费资讯重新收费。
- 资讯：现阶段不自建新闻站、不采购更多信源、不默认部署整套 AIHOT。先提供明确标识的 AIHOT 外部阅读入口，以及用户原创笔记/有权使用素材的输入。
- 发布：首版采用平台格式准备、复制/下载、打开平台和用户回填发布链接。自动发布、合作分销和私有部署不阻塞首版。
- 不增加第二套前端框架、消息总线、向量库或通用插件市场。视觉优先：原工作台直接复用，新增界面先用可审查原型确定。

## 3. 资讯整合与授权边界

AIHOT 的开源代码与 aihot.news 的服务/数据输出是两种权利边界。其公开规则说明：外部商业产品、收费服务、API 代理和批量再分发需要事先书面授权；页面某个区块免费、无需 API Key 或只展示摘要都不能替代授权。

首版采用 link-only：
1. 产品的发现入口打开 AIHOT 原站，新标签页显示来源，不冒充合作伙伴。
2. 用户把自己的选题、观点、原始出处 URL 和有权使用的材料带回工作台。
3. 对 AIHOT URL 只记录用户输入的链接，不自动抓取其摘要、缓存其数据或生成服务端预览；不得通过浏览器插件、用户粘贴或 AI 代理批量搬运绕过授权。
4. AIHOT 不可用时，用户仍能从个人素材直接创作。
5. 用户直接在原站浏览也应遵守原站规则；外链不是对后续商业数据复用的许可结论。

获得明确授权后，再做一个有范围、配额、到期日期和署名规则的资讯 connector。没有授权时保持关闭。仍不需要自建另一套新闻运营系统。更丰富信源、付费资料包、自动发现和自建采集均后置。

来源：https://aihot.news/terms （2026-11-16 核实，规则版本 1.1）

## 4. Magpie 在架构中的位置

这里的 Magpie 指 yetone/magpie，官方入口 usemagpie.ai，不是同名的其他项目。

```text
用户网页 / 外部 AI 的 MCP 客户端
              ↓
Media Desk 业务服务
  账户和工作区 / 内容 / 任务 / 积分 / 导出
              ↓
受控 worker + 小型 ModelProvider 适配层
              ↓
Magpie 网关（可选；独立进程或容器）
              ↓
已配置且获准使用的文本/图片 API

可选原生 CLI Runtime：保留给自托管/内部使用，不替代云端业务层。
```

Magpie 统一供应商、模型目录、协议转换、路由与用量观察；不是我们的客户账号系统、积分账本、持久任务队列、内容审核或 Agent 执行器。

### 4.1 最小接法

- 复用现有 OpenAI-compatible 文字 provider；新增 Magpie 类型和健康/能力检测，不嵌入 Magpie 完整桌面 UI，不 fork 其 Go 核心。
- 官方文档提供 `/api/hello`、`/v1/models`、`/v1/chat/completions` 等接口，图片模型与普通对话模型分开发现。
- 文本优先跑通。图片接口和目标模型须逐一做真实能力验收；不因存在统一端点就宣称全部图片提供方都兼容。保留现有直接图片 API 适配。
- 关闭 Magpie 时可显式选回直接 API；不暗中切换到收费更高或不同地域的供应商。
- 模型调用返回实际 provider、model、upstream request id 和 usage；缺少计费数据时标 unknown，不把估值写成已结算账单。

### 4.2 本地与云端

本地/自托管：用户可连自己运行的 Magpie、自己的 API 或已有外部 Agent。订阅账户仅在供应商条款允许的范围内使用；不宣传免额度限制。

云端：Magpie 作为私网 sidecar，worker 使用专用 gateway key。产品用户不接触供应商密钥或 Magpie 管理后台。生产镜像固定经测试的版本与 digest；不跟随 edge 自动升级。禁用自动发现运营者个人订阅账号，使用批准的按量商业 API。浏览器、MCP 和后台任务均通过业务服务鉴权与计费，不直接开放裸网关。

Magpie 的本机任意 key 标识语义不能当成云服务认证；容器/远程访问按官方 gateway-key 机制设置。管理端口只限管理员的内网/VPN访问。日志控制敏感正文保存，供应商 secret 不进入请求上下文或客户端。

### 4.3 路由与账务

固定标准/增强两类允许的模型路由，设供应商费用上限。fallback 仅在产品批准的模型、价格、能力和数据区域集合内发生。超时先核对上游结果；禁止应用与网关叠加无限重试。发生回退时记录每次供应商成本，但同一逻辑用户任务不重复扣用户积分。最终供应商费用以官方 usage/账单对账为准，Magpie 估算只是观察数据。

参考：https://usemagpie.ai/docs/integrate 、https://usemagpie.ai/docs/docker

## 5. 发布能力与合作方式

### 5.1 首版承诺

承诺交付可发布的内容包，不承诺全平台自动代发。

一个内容包应包含正文 Markdown/TXT、标题、摘要、标签、不同目标比例的图片、来源清单和导出 manifest。复制文本、下载图片/ZIP、打开平台、排期和回填已发布链接属于首版。复制富文本必须在实际目标编辑器验收，失败仍可使用纯文本和图片。

状态区分：draft → ready → exported / awaiting_user_publish；用户回填是 published_by_user（显示用户确认）。未来 API 提交受理是 submitted，只有平台回执确认才是 published。不得把下载、排期、外部接口 accepted 或手动勾选伪装成平台验证成功。

原版 Monid 是账号作品和指标导入依赖，不是发布服务；首版继续默认关闭，不为了发布引入 Monid 费用。

Postiz/Ayrshare 的已核实海外渠道不能直接等同于支持小红书、微信公众号或国内抖音。TikTok 不等于抖音。蚁小二官网的能力说明是候选依据，不等于已完成平台授权审计。

合作分三层：
- 推荐/联盟：用户自愿跳转与购买，我们可能获分佣；清楚披露，不把外链称为自动接通。
- 用户自带账号连接：用户授权现有发布工具，产品发送内容包并查询回执，第三方服务费用单独说明。
- 托管/白标 API：我们支付供应商并承接终端客户，必须先确认合同、授权、定价与故障责任。

推荐链接获批不代表取得 API 白标、转售或数据授权。开源发布器也不会自动免除平台开发者应用、OAuth、审核与维护要求。首版不集中保存用户平台密码/Cookie，不做绕过验证或自动化网页代发兜底。

后续启用发布：先有真实需求，建议以至少 5 位付费用户提出同一平台需求作为验证信号，再选一个渠道做试点。供应商最低成本、账号规模、授权、回执、撤权与失败演练通过后再开放。合作沟通目前仅准备问题，不自动发送邀约、不承诺费用。

## 6. 分阶段开发与验收

按验收门槛推进，不把以下阶段当成承诺工期。

### R0 · P0 · 基线与视觉

读取 PR #1 最新版本，审查测试报告和真实差异，记录是否合并的独立决定。冻结原 client/assets 参考。新增发现入口、创作简报、模型连接、结果/导出、钱包的视觉原型；原 Studio 不重绘。

完成条件：可审查的桌面和手机原型；旧页面无不必要改动；真实链路与未接通状态清楚标注；每项新增功能归属明确。

### R1 · P0 · Magpie 接入

在现有 provider 配置之上新增 Magpie；健康检测、动态模型目录、模型选择、取消超时、允许回退和 usage 记录。先文本后图片，直接 API 与 CLI 能力不被替换。合成测试不调用付费服务；真实模型测试在获准额度内单独进行。

完成条件：一条真实写稿请求有可追踪 provider/model；无模型、未授权、限额、超时和重复点击有准确结果；密钥不出现在前端/日志；关闭网关仍可显式改用原 provider。

### R2 · P0 · 创作到交付闭环

link-only 发现入口 + 用户选题/来源/观点卡；生成主稿、口播稿或封面。封面先选定 3:4 / 16:9 的有限模板，标题可编辑，不做自由设计器。新增浏览器下载 ZIP、文件 manifest 与手动发布记录。

完成条件：以 3 个真实选题走完来源→观点→正文/图片→编辑→下载→排期；随后再用 10–20 条内容验证质量。AIHOT 不可用不影响创作；无授权数据请求；手机能取到实际文件；原界面/MCP共享同一稿件。

R0–R2 后形成可自用的免费社区候选版；不宣称已是多人收费 SaaS。

### R3 · P1 · 云端账户与可靠任务

注册登录、工作区鉴权、私有对象存储、持久任务与取消、请求限流、邮件和运维。可沿用 PostgreSQL 任务模式；没有引入 AIHOT 后端时选一个最小 PostgreSQL job 实现，避免为复用队列拉入完整资讯系统。

完成条件：两个用户互读内容/文件/MCP请求均被拒绝；重启后任务不丢；结果权限正确；已知成功供应商请求不盲目再生成；受控无费用内测可完整交付。

### R4 · P1 · 积分、支付与运营

服务端预报价、价格版本、预留/结算/释放积分、幂等支付通知、退款和人工调整；供应商费用与用户账本分离；赠送积分防滥用；一个支付渠道先验收。此前价格和 API 成本均是待复核的候选，不自动成为正式价目。

完成条件：重复回调不多发积分、重复任务不重复扣费、余额不足不启动收费调用；部分成功按预先说明的交付组件结算；失败和退款可查；模型实际账单能追踪到任务。

### R5 · P1 · 受控发布与商业验收

服务器费用批准后部署测试/生产隔离环境，HTTPS、私有素材、备份恢复、回滚、告警。适用主体、支付、备案/登记、生成标识、隐私、退款和上游许可逐项核实。先少量真实用户，再扩大开放。

完成条件：生产授权与支付验收、数据恢复、供应商故障和质量样本均有证据。收入验证以付费作品交付和再次使用衡量，不以注册量/Star代替。

### R6 · P2 · 发布合作与更多资料

R2的发布交接接口保留扩展点，但不预建连接器市场。优先验证一个合作工具/渠道，额外信源只在真实用户需求和授权都成立时加入。自建资讯引擎、信息订阅收费、完整成片、机构私有部署、联盟市场等均不在首版关键路径。

## 7. 第一轮给开发者的任务合同

从 PR #1 和当前 main 开始，先交付 R0/R1/R2 的一条端到端候选：用户打开原工作台 → 选择来源链接或输入本人材料 → 补充观点 → 通过 Magpie 或现有直接 API 生成 → 编辑 → 浏览器下载真实内容包。

提交物：小范围 Draft PR、变更说明、自动化测试、桌面/手机截图、网络请求记录、脱敏 usage 样本、故障演练、已验证/未验证清单。合成夹具和真实模型运行分别标注；禁止把本地已装CLI当成账号可用或订阅供给已验收。

禁止顺带：重写原前端；合并未经审查候选；自建资讯站；自动使用 AIHOT 商业数据；安装自动发布机器人；复制平台密码/Cookie；使用个人订阅池服务付费客户；新增收费订阅、服务器或模型支出。需要费用时记录用途和限额供产品负责人确认。

## 8. 计划与实现分离

本文记录的是功能边界、依赖和验收计划，不是完成报告。合作工具当前只有公开资料核查，没有商务授权、费用报价确认或生产接入。开发执行和每次验收的证据应在任务中更新；代码变更使用独立 PR，不修改这份历史基线使未验证功能看起来已完成。
